# ADR 1. PostgreSQL for Relational Data and Auditing

## Context

We need to persist player records, injury logs, and user metadata while ensuring strict referential integrity and automatic system activity auditing.

## Decision

We chose PostgreSQL as our primary database engine. It allows us to enforce foreign key constraints, run native triggers (`log_audit_changes`) to audit database transactions, and leverage relational views for complex Business Intelligence reporting.

## Consequences

All player-injury associations are guaranteed to remain consistent. Modifying key records automatically writes to the audit log at the database layer, securing history tracking.
